## 2024-06-19 - IntersectionObserver nuances for scroll-based logic
**Learning:** When using `IntersectionObserver` to replace scroll event listeners for elements that should animate when scrolled into view, it's critical to include a check for `entry.boundingClientRect.top < 0`. This is because elements that are already above the viewport (e.g. after a page refresh midway down the page) might not trigger the `isIntersecting` check when the observer initializes, preventing them from receiving their active classes. Also, a guard clause like `if (elements.length === 0) return;` prevents unnecessary observer initialization if the class is unused.
**Action:** Always include `entry.isIntersecting || entry.boundingClientRect.top < 0` when checking intersection for scroll reveal animations, and use guard clauses before initializing observers.
