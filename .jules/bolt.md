## 2024-05-24 - Layout Thrashing with getBoundingClientRect
**Learning:** The static `index.html` application utilized a scroll event listener coupled with `getBoundingClientRect()` to calculate visibility of elements for scroll-revealing animations. This is a common performance anti-pattern that causes synchronous layout recalculation (layout thrashing), severely degrading main thread performance and scroll framerate, especially since it fires on every scroll tick.
**Action:** When inspecting scroll-based animations in similar single-file frontend codebases, look for synchronous DOM reads (like `getBoundingClientRect`, `offsetTop`, etc.) inside scroll listeners. Replace them with `IntersectionObserver` to offload visibility calculations from the main thread and avoid forced reflows.
